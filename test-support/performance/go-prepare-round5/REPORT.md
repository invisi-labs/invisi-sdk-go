# 默认启用 Go 原生 Protocol RPC 传输

此前显式开启，是为了保留缺省客户端使用可由应用修改的 `http.DefaultTransport` 的行为。部署服务核验的复用要求传输策略由 SDK 控制，因此旧默认客户端仍多查一次服务。现在，未提供 `HTTPClient` 时直接采用 SDK 私有原生传输；默认预热也可复用同一在线构造、同一客户端和连接 epoch 上仍有效的部署核验，从 4 次降为 3 次，不需要设置开关。

仅修改构造器的缺省传输选择，没有修改来源证明、缓存失效、历史锚点、持久化或恢复逻辑。Git HEAD 保持 `9182fc870449afddbf8fef5a110b1c40e059ffdd`，没有 rebase develop、提交、部署或真实广播。

## 默认与自定义客户端的边界

| 调用方式 | 传输 | 空钱包普通 Shield 额外预热请求 |
|---|---|---:|
| 不传选项，或零值 `ClientOptions{}` | SDK 私有连接池 | 3 |
| `UseNativeHTTPTransport: true` | 相同私有连接池，保留兼容 | 3 |
| 提供自定义 `HTTPClient` | 保留调用方的传输、超时等策略 | 4 |
| 提供 `HTTPClient: &http.Client{}` | 沿用全局 `http.DefaultTransport` | 4 |

自定义客户端仍保留既有的重定向拒绝策略；`UseNativeHTTPTransport: true` 与自定义客户端同时设置仍报错。默认客户端维持 30 s 超时、复制请求头、标准 TLS、环境代理与重定向拒绝。需要继承应用对全局默认传输的修改时，显式传入 `HTTPClient`，并按需要设置超时。

3 次预热仍包括：最新区块 `eth_getBlockByNumber`、实时网络 `eth_chainId`、要求 canonical 的 Token `eth_getCode`。构造期核验失效、来源改变、连接 epoch 改变或离线恢复时，仍实际重新认证服务；普通路径的 3 次不是所有恢复场景的固定请求承诺。公共 `GetDeployment` 继续实际查询，开始更新即撤销旧证明，包括失败与取消。完整同步的服务认证和按区块固定的部署读取没有变化。

## 同一套诊断的结果

前后分别冻结源码并独立构建二进制，使用逐文件哈希相同的诊断驱动。主对比的 `NATIVE_SERVICE=0`，明确没有开启开关；顶层 `nativeServiceAdoptions` 记录是否设置旧开关，不能把它当成最终使用的传输。默认私有传输的选择另外通过真实 HTTP 回归验证：应用修改的全局传输无法截获默认请求，自定义传输和自定义 nil 传输则按原策略收到请求。

每组 3 个 fixture，各连续两笔，实际选择并消费 nonce 7、14，保持第一笔日志不被第二笔修改。每笔仍为 7 次：准备网络/nonce 2 次、报价 2 次、提交网络/状态/最终网络 3 次；本地资金签名为 0 次。冷构造与既有广播器初始化全部计入，最内层拒绝的写请求没有出站。

耗时为 ms，取 3 个 fixture 的中位数。完整成本先按各 fixture 求和再取中位数；每笔写请求都在最内层被拒绝，并未计作实际已发 HTTP。

| 组别 | 额外预热请求 | 初始化请求/耗时（含原有 3 次） | 首笔交易请求/耗时 | 第二笔请求/耗时 | 首笔含全部启动请求/耗时 |
|---|---:|---:|---:|---:|---:|
| 修改前默认 | 4 | 7 / 160.08 | 7 / 186.82 | 7 / 186.79 | 21 / 500.07 |
| 修改后默认（不开标志） | 3 | 6 / 135.81 | 7 / 189.13 | 7 / 190.79 | 20 / 480.69 |
| 修改前自定义 HTTPClient | 4 | 7 / 150.88 | 7 / 188.10 | 7 / 187.08 | 21 / 497.50 |
| 修改后自定义 HTTPClient | 4 | 7 / 153.07 | 7 / 194.81 | 7 / 192.36 | 21 / 508.48 |
| 修改后显式旧标志 | 3 | 6 / 134.87 | 7 / 189.54 | 7 / 186.78 | 20 / 481.39 |
| 修改后默认，EIP-1898 回退 | 5 | 8 / 178.91 | 7 / 191.80 | 7 / 191.35 | 22 / 524.65 |

所有组的冷构造均为 7 次。默认模式首笔完整请求 **21→20**，中位数 **500.07→480.69 ms**；两笔合计含启动 **28→27** 次，**686.87→671.49 ms**。初始化阶段含原有广播器初始化为 **7→6** 次、**160.08→135.81 ms**。本轮减少的是预热请求，每笔交易仍各 7 次。自定义客户端的请求数没有变化，其时间样本存在波动，不据此主张性能改善。

6 组共 252 个阶段记录全部通过独立核对：相同场景、相同驱动文件 SHA-256、正确的开关状态、实际请求数、最新 nonce 标签、无交易内重复区块/代码查询、每笔一次传输拒绝，以及冻结输入与当前源码逐文件一致。

各计时组在完整测试结束后串行执行，每次 HTTP 响应固定延迟 20 ms，统计通过真实本地 HTTP/TLS 产生的请求。它验证 SDK 网络行为与成本差异，不代表公网节点、App 或成交时间。自定义服务对照使用 TLS 客户端，绝对耗时单列。EIP-1898 回退将失败探测也计入：默认预热 5 次，另加广播器初始化原有 3 次；后续仍各 7 次。注册表、钱包检查点及其他交易类型不包含在本次固定数量中。

## 回归与全量检查

先写回归再修复：无选项、零选项均命中可变全局传输且证明不能复用；会话默认预热服务查询为 2 次（含构造）而非预期的 1 次。这三项在修改构造器前实际失败，见 [RED 日志](red.log)。修改后定向 race 检查通过，包含自定义客户端、来源更新失败/取消、离线恢复、被替代的捕获及部署高度检查，见 [定向日志](focused-race.log)。

本轮源码差异核对仅有一个生产文件：`rpc/client.go`。仍先拒绝显式原生标志与自定义客户端的冲突，只在缺少客户端时安装私有传输，其余客户端复制和重定向行为未改。原先依赖一次新鲜服务查询的初始化并发回归改用自定义客户端，继续覆盖该竞争分支；默认预热的精确计数则单独断言构造后不再重复查询。

现有检查继续覆盖：代次和检查点失效、网络切换、落盘后第一次发送围栏、版本 2 日志与旧版本拒绝、原子持久化、未知提交结果的原包重放、已知 ID 的只查状态。冻结包恢复沿用原客户端和原包，不依赖重新创建准备缓存。

- 八个独立提取的本地归档分别运行测试、vet、build 全部通过，脚本退出 0；没有发布。
- 定向 race 通过（RPC 1.725 s、session 2.786 s，均是测试运行时间）；六组零延迟功能诊断与六组串行 20 ms 诊断通过。所有计时均在全量检查结束后进行。
