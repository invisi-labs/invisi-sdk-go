# Go 费用锁票据有效期内复用

基线是已经完成能力初始化复用的 Go SDK（HEAD `a51f78dae98b11093f388e2e86c2df8b822cfc3e`，含原有未提交优化）。本轮保留签名票据的价格承诺，在相同绑定与有效期内复用；没有再次 rebase、提交、发布或真实广播。

## 为什么可以复用

实际广播器 `invisi-broadcaster/internal/service/fee_lock.go` 将票据定义为可复用、有绝对期限的 Core 费率。签名绑定链、Protocol、signer、Token、feeRecipient、模型，以及票据自己的价格比率、gasPrice、markup、gasMargin、maxGas、deadline。它不绑定 payer nonce、交易金额或 calldata。服务端每次仍按真实交易重新计算 gas，并检查票据和当前服务的 gas 上限；最终报价不能超过票据与交易的期限。

初始化过的原始客户端只保存一个私有内存票据槽。复用还要求初始化能力票据、客户端配置、发现来源、原生 epoch 和 HTTP 策略仍有效。每次命中及实际报价调用均验证签名、绑定和期限；每个操作获得独立的票据与 trust 副本，调用方的可变整数和其他操作不能改变它。槽不序列化、不跨客户端、没有全局缓存。未初始化路径保持原先实时发现与获取票据的行为。

价格源刷新不是已签署费率承诺的失效条件。过期、Token 或其他绑定改变则重新获取；一个槽的有界设计也意味着切换 Token 后再切回可能重新获取。初始化替换、失败或能力票据退休会清空槽，旧响应不能覆盖新票据或复活旧权限。I/O 与来源校验回调在锁外执行。并发冷缺失可以各自获取票据，只有最新有效获取可发布到共享槽。

精确结构化拒绝 `-32040/FEE_LOCK_EXPIRED`、`-32041/FEE_LOCK_INVALID`、`-32042/FEE_LOCK_GAS_EXCEEDED`，或本地发现票据无效，会按对象身份仅清除匹配的缓存。旧操作的错误不会清掉新票据；一般网络错误、同码异因或异码同因不被当成票据拒绝。当前定价失败后仍原子保留原来的未签名业务计划，重试获取新票据。不会在操作中途切换费率、自动退回无锁报价，或重写已授权/冻结的交易。已签报价及原包重放、已知 ID 状态查询的恢复规则不变。

## 请求与计时

**首次冷缺失仍为 8 次；有效期内相同绑定的后续交易为 7 次。** 过期或更新绑定的获取成本没有隐藏到初始化。普通无费用锁场景仍各 7 次，初始化总请求仍为 6 次（广播器 3 + Shield 预热 3），冷构造仍为 7 次。

沿用同一原生实际 HTTP 驱动，前后分别冻结源码、独立编译；同一 fixture 连续两笔真实选择并消费 nonce 7/14，检查第一笔日志不被第二笔改写。费用锁 fixture 实际签发票据，估算和签名报价均检查传入票据绑定和签名。前后驱动文件逐字节相同。

耗时单位为 ms，取 3 个 fixture 的中位数；完整成本在各 fixture 内相加后取中位数。

所有计时组在 Go 和 TS 的重负载验证结束后串行运行，每个 HTTP 响应固定延迟 20 ms，真实访问本地 HTTP/TLS。3 个独立 fixture 的中位数及范围见原始汇总，完整成本先按 fixture 求和再取中位数。样本包含本地调度、密码学计算波动，不代表公网/App 或成交时间。最终写请求在最内层拒绝，未出站，不计作实际已发请求。
