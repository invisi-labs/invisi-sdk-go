## Contract

1. Initialization owns stable deployment/code/version/registry/service capability facts under explicit connection/source/policy lifetime.
2. Prepare selects and freezes business inputs, funding authorization mode, funding nonce/deadline and pinned preparation facts. Quote does not select a nonce. Default signature funding reads the nonce in prepare, exactly once per operation, including Rust initialized Shield. Explicit caller-selected nonce remains explicit and must retain required validation. A caller-funding→signature transition cannot silently pick nonce inside quote; require explicit preparation if a prerequisite is unavailable.
3. Quote performs fee-only/budgeted repricing using already prepared facts. It must not call the general prepare/prepareIntent/prepareShield/prepareTransfer pipeline or redo deployment/head/nonce validation. Rebuild final calldata/commitments/delivery locally from frozen resolved facts where fees change funding/change. Maintain max fee, funding permit, schedule/aggregate, fixed outputs/grant IDs and rollback semantics. If a new business input/state resolution is genuinely required, return an explicit need-to-reprepare error before mutating the original operation; callers prepare again with appropriate input/budget. Do not make a fake success by ignoring missing facts or altering signed/attempted authority. Existing pure local fee adjustment is allowed.
4. Authorize/prove/ready own signatures and all required proof artifacts. `ready` success means main proof, final funding signature/calldata and required Source/Provenance sidecars exist and bind the final statement. **For every required-Source private flow, main prove publishes only proved; ready/finalize generates Source evidence after the final statement/signatures are known.** This applies with or without public funding, giving all SDKs one contract and preserving the completed main proof if Source finalization fails. **Do not move Source proving into a signing/export method.** Attaching the final funding signature remains local/explicit verifier work and leaves a required-Source operation awaiting explicit ready/finalize. Existing auto-ready transitions without Source/private inputs can remain compatible because they only encode/check local data. No new public journal phase is necessary solely for this distinction; use the existing proved/prepared intermediate with an explicit finalization requirement. Recursive/aggregate main phases may remain proved while an explicit finalized broadcaster envelope carries submit-ready evidence; do not mislabel it as exportable EVM calldata. Keep explicit reprove for changed Source trust without changing native payment data. Missing capability/proof errors must be atomic, without publishing a partially ready durable record. Contract-wallet/custom online verifier semantics remain explicit and safe.
5. First submit consumes completed immutable artifacts. It must never call a prover, signer, nonce selection, general preparation or repricing to fill missing artifacts. Retain local envelope/proof validation, live mutable service requirements, necessary current execution/network checks, atomic durable externalization, and a final network/provider/policy/wallet fence after awaited persistence and immediately before wire. Known-not-externalized refusal rollback rules stay exact; no rollback for previously exported/uncertain authority.
6. Recovery of an attempted packet bypasses fresh quote/nonce/proving and preserves the exact original packet/client. Known ID queries only status; unknown ID replays bytes. Initialization/cache retirement never discards attempted obligations or reservations. Missing unsigned restored evidence is an explicit finalization/revalidation requirement, never silently repaired in submit.
