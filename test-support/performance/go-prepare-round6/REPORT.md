# Go 报价能力复用：初始化不新增请求

本轮基于已经 rebase develop 的 `a51f78dae98b11093f388e2e86c2df8b822cfc3e`。目标是复用初始化时取得的报价能力，去掉逐笔 `ForPreparation` 的 `broadcaster_getStatus`，保留提交前的实时服务检查和每次费用锁票据的验证。没有再次 rebase、提交、发布或真实广播。原有未提交优化继续保留。

## 放到哪里，以及复用什么

现有 `InitializeBroadcasters` 已执行 Token 支持检查。实际广播器实现的 `GetTokenSupport` 返回 `TokenSupport{ServiceStatus: a.GetStatus(), TokenAddress: token}`，因此该响应已经包含报价能力。只需严格解析并校验现有响应，无需在初始化再发一次 `getStatus`。证据来自本地 `invisi-broadcaster/internal/service/api.go` 的 `GetStatus` 与 `GetTokenSupport` 实现。

显式初始化的原生、可复用发现路径保存私有能力结果，绑定具体客户端、部署、注册 signer/recipient、发现票据、原生连接 epoch 和 HTTP 策略。普通 `SupportsToken` 不授予缓存权限；未初始化客户端保持原来的实时能力发现。静态地址配置和 JSON 都不能创建这种结果。

显式初始化替换或失败即撤销旧票据；旧句柄也不能恢复旧权限。网络、HTTP 策略或发现票据失效后，需要重新成功初始化。服务查询返回相同且有效的能力时保持复用；失败、取消、格式错误或能力改变只撤销该查询开始时观察到的票据，迟到的旧失败不会撤销新初始化。网络 I/O 不持有缓存锁。

费用锁能力与签名票据分开：能力可以复用，**每个启用费用锁的操作仍获取新票据**，保留链、Protocol、Token、recipient、signer、模型、签名、期限与 gas 上界检查。票据失败不会自动退回无锁报价。提交前继续实际检查暂停状态、provenance 等要求。能力变化会禁止后续使用旧能力定价；已经获得的有效签名报价仍按自身提交规则判断，费用票据不被当成额外交易授权。冻结包重放与已知 ID 查询不依赖重新获得准备缓存。
